# فرانت‌اند لندینگ‌پیج

کد در `../web/`. بیلد پروداکشن تمیز، ۲۴ فایل، حدود ۲۰۰۰ خط.

```bash
cd ../web && npm install && npm run dev
```

## استک

| لایه | انتخاب |
|---|---|
| فریم‌ورک | Next.js 15، App Router، اکثراً Server Component |
| استایل | Tailwind v4 با `@theme` در `app/globals.css` |
| حرکت | GSAP برای تویین، IntersectionObserver برای تریگر |
| سه‌بعدی | Three.js، شیدر سفارشی، lazy و client-only |
| آیکون | `@phosphor-icons/react` |
| فونت | Vazirmatn از Google Fonts |

## تصمیم‌های فرانت

**هر سکشن مستقل خراب می‌شود، نه کل صفحه.** هر تابع API روی خطا `null` برمی‌گرداند
و هر سکشن یا fallback دارد یا رندر نمی‌شود. سند طراحی هم همین را الزام کرده بود.

**مسیرهای API یکسان‌سازی شد.** سند در دو جا ناسازگار بود (`/api/v1/public/...` و
`/public/...`). همه زیر `/api/v1` رفت.

**فرم لید کوتاه شد.** سند نام، ایمیل، موبایل، نوع کاربر، بازه سنی، علاقه‌مندی و زبان
می‌خواست. ایمیل و بازه سنی حذف شد: در ایران ایمیل کانال فعال‌سازی نیست و هر فیلد
اضافه حدود ۱۰ درصد نرخ تبدیل می‌خورد. ماند: نام، موبایل، نوع کاربر، علاقه‌مندی، رضایت.

**Social Proof بدون داده واقعی رندر نمی‌شود.** نظر ساختگی روی صفحه نمی‌رود.

**هیرو به چهار عنصر متنی محدود شد.** badge، تیتر، زیرتیتر، دکمه‌ها. چیپ‌های
highlights که سند در هیرو گذاشته بود به Trust Strip منتقل شدند تا هیرو در یک
نمای صفحه جا شود.

## سه باگ واقعی که پیدا و رفع شد

### ۱. `clip-path: path()` واحد پیکسل مطلق دارد

ماسک طاق با `clip-path: path("M0 100 V46 ...")` نوشته شده بود. آن مختصات پیکسل
مطلق‌اند، نه درصد، پس هر تصویری به جعبه ۱۰۰ در ۱۱۰ پیکسل بریده می‌شد.

**رفع:** `<clipPath clipPathUnits="objectBoundingBox">` در `layout.tsx` با مسیر
`M0,1 V0.42 Q0,0.05 0.5,0 Q1,0.05 1,0.42 V1 Z` و `clip-path: url(#arch-clip)` در CSS،
به‌علاوه fallback با `border-radius` زیر `@supports not`.

### ۲. `gsap.from` روی کل صفحه محتوا را نامرئی می‌کند

`gsap.from(targets, {opacity: 0})` همه هدف‌ها را از ابتدا روی opacity صفر می‌گذارد.
هر پرش اسکرول ــ لینک لنگر، بازیابی موقعیت مرورگر، جستجوی درون‌صفحه ــ بخش‌هایی را
سفید می‌گذاشت که هرگز نمایان نمی‌شدند.

**رفع:** فقط عناصری که در لحظه راه‌اندازی **واقعاً پایین‌تر از خط دید** هستند مخفی
می‌شوند. اگر جاوااسکریپت اجرا نشود یا کاربر وسط صفحه بیفتد، همه‌چیز دیده می‌شود.
HTML سرور هم هیچ `opacity: 0` ندارد، پس بدون JS کامل خوانده می‌شود.

### ۳. تور ایمنی نباید به `requestAnimationFrame` وابسته باشد

تور ایمنی اولیه خودش `gsap.to` بود. در تب پس‌زمینه مرورگر rAF را متوقف می‌کند و
تویین GSAP وسط راه یخ می‌زند ــ یعنی خود تور ایمنی هم یخ می‌زد و محتوا نیمه‌شفاف
گیر می‌کرد.

**رفع:** تور ایمنی مستقیم روی `element.style` می‌نویسد و به `visibilitychange`
هم گوش می‌دهد.

> این باگ موقع دیباگ در پنل مرورگر این جلسه کشف شد که rAF را کامل متوقف می‌کند.
> اگر روزی دیدی انیمیشن‌ها وسط راه یخ زده‌اند، اول چک کن rAF زنده است:
> `new Promise(r=>{let n=0,t=performance.now();const l=()=>{n++;performance.now()-t<1000?requestAnimationFrame(l):r(n)};requestAnimationFrame(l)})`

## `Reveal` چطور کار می‌کند

تریگر **IntersectionObserver** است نه `ScrollTrigger`. دلیل: ScrollTrigger موقعیت‌ها
را یک‌بار اندازه می‌گیرد و بعد از تغییر ارتفاع (بارگذاری فونت و تصویر) یا پرش
ناگهانی اسکرول نیاز به `refresh()` دارد؛ در عمل باعث می‌شد بخش‌هایی روی opacity صفر
گیر کنند. IntersectionObserver با چیدمان فعلی کار می‌کند.

GSAP همچنان تویین را اجرا می‌کند. سه قاعده ایمنی:

1. فقط چیزی که واقعاً پایین‌تر از دید است پنهان می‌شود
2. اگر تا سه ثانیه چیزی تریگر نشد، همه‌چیز بی‌قید نمایش داده می‌شود
3. زیر `prefers-reduced-motion` اصلاً چیزی پنهان نمی‌شود

## `HeroCanvas` چطور کار می‌کند

صفحه‌ای با شیدر که سه موج هم‌نهاده با فرکانس‌های ناهم‌ساز تولید می‌کند و به موقعیت
اشاره‌گر واکنش نشان می‌دهد. رنگ‌ها از پالت کاشی: فیروزه‌ای در دره‌ها، زعفرانی در تاج موج.

محافظت‌های عملکردی:

- `import("three")` پویا، فقط سمت کلاینت
- روی `prefers-reduced-motion` یا عرض کمتر از ۷۶۸ اصلاً بارگذاری نمی‌شود
- `IntersectionObserver` رندر را وقتی هیرو از دید خارج شد متوقف می‌کند
- `devicePixelRatio` سقف ۱٫۷۵
- `ResizeObserver` برای تغییر اندازه
- پاک‌سازی کامل: `cancelAnimationFrame`، حذف listener، `dispose()` روی geometry و
  material و renderer

## سکشن دمو

پیچیده‌ترین کامپوننت. طبق سند **پخش واقعی** است نه شبیه‌سازی.

- منبع حقیقت پیشرفت، خودِ `<audio>` است؛ state رابط از رویدادهای player می‌آید
- تعویض صدا منبع صوتی را عوض می‌کند و نام گوینده از `source.voiceName` می‌آید،
  نه از `sampleBook`
- انتخاب پیشنهاد `audio-item` جدید می‌گیرد، پخش را متوقف می‌کند، پیشرفت را صفر می‌کند
- صدایی که برای کتاب فعال `source` ندارد در رابط disabled می‌شود ــ همان قرارداد MVP سند
- `seek` روی نوار پیشرفت با **مبدأ راست** محاسبه می‌شود چون صفحه RTL است
- حالت کودک state محلی است و در حساب کاربر persist نمی‌شود
- خطای بارگذاری صوت سکشن را می‌شکند نه صفحه را

## نکات RTL

- `dir="rtl"` روی `<html>`، `lang="fa"`
- از ویژگی‌های منطقی استفاده شده (`ms-`, `me-`, `inset-inline-start`) نه `ml-`/`mr-`
- بلوک‌های لاتین (شماره تلفن، ایمیل، تایم‌کد) `dir="ltr"` با `text-align: right`
- محاسبه `seek` معکوس

## کارهای باقی‌مانده

- تصاویر از `picsum.photos` با seed توصیفی‌اند، جای عکس واقعی
- شماره تماس فوتر با `[شماره تماس]` علامت خورده
- فایل صوتی نمونه در `lib/demo-fallback.ts` باید با نمونه واقعی عوض شود
- صفحات `/privacy` و `/terms` ساخته نشده‌اند و **برای اینماد لازم‌اند**
- انیمیشن‌ها و شیدر در مرورگر واقعی بصری تأیید نشده‌اند (پنل این جلسه rAF نداشت)
- `POST /leads` هنوز rate limit و honeypot و تأیید پیامکی ندارد
